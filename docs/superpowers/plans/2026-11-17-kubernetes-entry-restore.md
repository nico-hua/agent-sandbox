# Kubernetes active 入口启动恢复实施计划

> 执行方式：superpowers:executing-plans；逐项先写失败测试，再实现与验证。

**目标：** 在应用独占 SQLite 期间，为一批原 active 实例恢复应用拥有的入口，默认关闭。
**依据：** 本轮用户提供的七部分需求；不自动恢复 pending、不修改资源和记录、不自动重连。
**架构：** Store 有界选择；Service 验证记录、工作区与凭据；Kubernetes 启动协调器只负责解析目标和管理会话。沿用 lifespan 清理和 RunLock。

## 验证重点

- TTL 只用数据库当前期限；资源初始期限不参与候选过滤。
- 槽位由现有 manager.open 原子准入；启动/未确认关闭都计数。
- 原凭据在 Service 比较，协调器与摘要不持有明文。
- 仅关闭本轮新建且目标完全匹配的会话；失败关闭保留句柄和锁。
- 启动时间预算只限制新候选；已开始工作必须收尾，非严格总 deadline。
